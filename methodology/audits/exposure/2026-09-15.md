## 2. Warn dispositions for the added files

**PII, "email address", 6 findings. ACCEPTED.**

- `tests/fixtures/request-capture/req-0003.json:35` and `req-0005.json:35`.
  These are the two main turns of the sanitized capture fixture. The real
  capture carries the founder's account address, because the vendor's own
  reminder block puts it in every request; the fixture replaces it with the RFC
  2606 documentation address before anything is committed, and the raw capture
  is not in the repository and never will be.
- `tests/request-proof.test.ts:6,210,217,568`. The same documentation address in
  the test that asserts the check finds the reminder block, plus one address in
  a `.co.uk` form in the redaction test, which exists to show the replacement
  works on a template the account address does not use.

All six are documentation addresses chosen because they cannot belong to anyone.
The scanner has no way to know that and should not be taught to guess, so they
stay as warnings and the disposition is recorded here rather than by loosening
the rule.

## 3. Deliberate non-exposure in the same batch

Three things the batch handles by not committing them, recorded because each
would otherwise be a fail-class finding on the next full audit:

- **The vendor default system prompt.** 6,755 characters of Anthropic's own
  prompt under the pinned seat. `scripts/panel/request-proof.ts` pins it by
  SHA-256 and the fixture carries a stand-in, so the check is exact and the text
  is not republished. The session-naming prompt, the two client tool
  definitions, the session-title trailer and the fetch-summarizer suffix are
  handled the same way.
- **The raw captures.** The feasibility probes and the live diagnostic all hold
  the founder's account address, account UUID and device id. They stay outside
  the repository. The committed fixture was derived from the live diagnostic
  with the address replaced, the identifiers zeroed and the working directory
  replaced with `/stub/work`.
- **The CLI executable path.** The launcher resolves and retains it privately in
  the attempt metadata; `scripts/panel/attempt-record.ts` does not copy it into
  the public manifest row, because it names a path on the founder's machine.
